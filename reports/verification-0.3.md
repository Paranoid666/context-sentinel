# 0.3.0 主动提醒验证

核实日期：2026-10-11，Asia/Hong_Kong。环境：Windows / Python 3.12.10。依赖未新增，使用原 MCP SDK 1.30.0 和 Pydantic 2.14.0。

## 已实际验证

- **60 项 pytest 全部通过**。结果见 pytest-0.3.xml；包含原有交接/恢复测试与新增提醒测试。
- 真实 MCP stdio 子进程中，monitor_open → monitor_observe → migration 提醒 → monitor_ack → 事件重放保持安静。
- 实际 reminder_demo.py 在第 3 个观察轮次给出保存提醒，第 5 个轮次给出换聊提醒（仅演示阈值缩短）；重启后恢复计数，已确认的事件重放不再次提醒。结果见 reminder-demo.json。
- 不同事件但相同 turn_id 仅计一轮；相同事件幂等，不同内容复用事件 ID 被拒绝；并发调用只生成一个提醒。
- 提醒展示确认后，同级提醒需同时经过轮数与时间冷却；风险升级绕过冷却；旧提醒确认不误清除新提醒。
- 风险下降撤销/替换未展示的过时提醒；关闭模式或暂缓期间不提醒；新聊天的监控计数独立。
- JSONL 宿主事件入口能处理风险事件并返回提醒，错误输入返回错误类型、不回显输入内容。
- SKILL.md 通过 skill-creator quick_validate。

## 实现方式与实际边界

AI 任务内模式：技能明确要求每轮/阶段边界/验证失败主动检查，再向用户显示待发送提醒。该指令已写入技能和 MCP server instructions，但本次没有在已安装该技能的独立真实 Codex 聊天中验证模型是否每轮遵守；不能承诺模型绝不漏调用。

宿主模式：CLI watch 或 MCP 接收实际宿主事件。已验证输入到来时自动形成提醒；当前桌面宿主的原生 turn 回调尚未连接。没有自动获取聊天正文、内部 token 遥测、后台定时器、系统弹窗或窗口切换。

提醒投递为“展示后确认”的至少一次协议；展示后确认前崩溃时，宿主应按 reminder ID 去重。没有声称严格 exactly-once UI 投递。提醒确认不等于用户授权新建线程，也不等于交接恢复确认。

默认启用规则是 16/48 个已观察轮次、8 轮且 600 秒同级冷却。此配置只有在服务收到观察事件时才生效。构建交付不会自动安装全局技能或修改宿主 MCP 配置。

0.2.0 的真实 App Server 创建记录仍作为历史证据保留；本次没有再次创建外部线程或执行模型回合。
